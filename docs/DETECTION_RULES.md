# DataReady v0.1 检测规则

这份文档描述当前规则边界。它既是产品说明，也是后续增加测试用例时的基线。

## 1. Missing

识别：

- `null / undefined`；
- 空字符串；
- 常见显式空值编码，如 `N/A`、`NA`、`null`、`None`、`-` 等。

原则：

- 显式空值编码可以建议统一成 Missing；
- 不自动选择均值 / 中位数 / 众数填充；
- 缺失率高时提高问题等级，但不自动删行。

## 2. Exact Duplicate

使用全行标准化值生成稳定行签名，识别整行完全重复。

原则：

- 属于低风险清洗；
- 可以默认加入 Cleaning Plan；
- Preview 告知预计删除行数。

v0.1 不自动处理“业务键相同但其他字段不同”的疑似重复。

## 3. Type Anomaly

基于字段整体分布判断 Numeric / Date 等类型，再查找与主类型冲突的单元格。

原则：

- `"1,200" -> 1200` 这类可确定转换可以建议自动处理；
- `"待核对"` 这类无法解释的文本只标记，不伪造数值。

## 4. Category Inconsistency

v0.1 结合：

- trim；
- 大小写；
- 空格 / 常见连接符规范化；
- 内置 alias；
- 轻量字符串近似。

原则：

- “长得像”不等于“一定同义”；
- 类别语义合并属于 Medium Risk；
- 默认需要用户确认。

## 5. Outlier

数值字段默认使用稳健的 IQR 思路识别显著异常值，并采用较保守阈值降低误报。

原则：

- Outlier 是“值得检查”，不是“错误”；
- 不默认删除；
- 不默认 Winsorize；
- 展示分布上下文和影响行数。

## 6. Date / Time

识别：

- 可解析日期；
- 混合日期格式；
- 非法日期；
- 如果存在创建 / 完成时间字段，检查明显顺序冲突。

原则：

- 无歧义格式标准化属于低风险；
- 语义冲突只提示，不自动改时间。

## 7. Constant / High Uniqueness

识别：

- 唯一值数量为 1 的常量字段；
- 唯一率非常高且更像 ID / Free Text 的字段。

原则：

- 只解释其分析含义；
- 不默认删除字段。

## 8. Basic Business Logic

v0.1 只加入非常通用、可解释的弱规则，例如：

- `orders = 0` 且 `gmv > 0`；
- 金额出现负值时提示检查；
- 明显的时间先后冲突。

这些规则不能替代真实业务口径。系统文案应该使用：

> “可能的数据异常 / 请确认是否为真实业务情况”

而不是：

> “业务错误 / 必须修正”

## 9. 严重程度

### Critical

有较高概率直接污染分析结果，且问题本身相对明确，例如完全重复、明确类型错误、非法日期、明确时间逻辑冲突。

### Warning

需要业务判断，例如异常值、类别疑似重复、较高缺失、弱业务逻辑异常。

### Suggestion

优化类提示，例如常量字段和高唯一值字段。

## 10. 安全底线

无论规则置信度多高，以下操作都不应在 v0.1 默认执行：

- 删除异常值；
- 修改业务数值；
- 用统计值填补缺失；
- 删除大量数据；
- 语义类别合并。
